# Paper Card: OLMo — Accelerating the Science of Language Models

## 논문 정보
- **제목**: OLMo: Accelerating the Science of Language Models
- **저자**: Groeneveld et al. (Allen Institute for AI)
- **발표**: ACL 2024 / arXiv:2402.00838
- **모델**: OLMo-1B, OLMo-7B

## 핵심 주장
> "투명성이 과학적 연구를 가능하게 한다"
> 가중치·데이터·코드·체크포인트 전체 공개 → 재현·확장·인과추적 가능

## 논문 근거 3가지

### 1. 연구 가능성
가중치/데이터/코드가 없으면 모델 편향, 위험성, 한계를 분석 불가

### 2. 재현 가능성
논문 결과를 다른 연구자가 검증하려면 전체 파이프라인 공개 필수

### 3. 인과 추적
체크포인트가 있어야 "어느 학습 단계에서 어떤 능력이 생겼는가" 추적 가능

## 공개 아티팩트
| 항목 | 내용 |
|---|---|
| 모델 가중치 | 1B, 7B + 500개 이상 중간 체크포인트 |
| 학습 데이터 | Dolma (2.7T 토큰, Common Crawl 88.8%) |
| 학습 코드 | PyTorch FSDP + ZeRO optimizer |
| 평가 프레임워크 | Catwalk (downstream), Paloma (perplexity) |
| 적응 코드 | Open Instruct (SFT + DPO) |
| 라이선스 | Apache 2.0 |

## 아키텍처 (7B 기준)
| 항목 | 설정 |
|---|---|
| 구조 | Decoder-only Transformer |
| Activation | SwiGLU |
| Positional Embedding | RoPE |
| Layer Norm | Non-parametric |
| Optimizer | AdamW (lr=3e-4, warmup=5000 steps) |

## 우리 실험과 연결

| 논문 근거 | 우리 실험 |
|---|---|
| 연구 가능성 | 실험 1: 체크포인트 268개 확인 |
| 재현 가능성 | 실험 2,3,4: 패턴·SFT·도메인 재현 |
| 인과 추적 | 실험 2,4: Base→SFT→Instruct 단계 추적 |

## 한계

- 논문 원본 7B → 우리 실험 1B (스케일 차이)

# Project Canvas: 발달장애 근로자 직장 의사소통 훈련 서비스

## 문제 정의
발달장애 근로자는 직장 내 의사소통 상황에서
적절한 언어 표현을 선택하는 데 어려움을 겪는다.
기존 훈련은 오프라인 매뉴얼 중심으로 반복 실습이 어렵다.

## 솔루션
OLMo 공개 가중치 기반 도메인 파인튜닝 모델로
상황별 언어 피드백과 표현 선택지를 실시간 제공하는 LLM 훈련 서비스

## 서비스 구조
사용자 입력 (직장 상황 텍스트)
↓
도메인 파인튜닝 모델
(OLMo2-1B + 발달장애 직장 매뉴얼 500개 LoRA SFT+DPO)
↓
언어 피드백 + 표현 선택지 3가지 제공
## 데이터 출처
| 출처 | 건수 | 내용 |
|---|---|---|
| 장애인고용공단(KEAD) | 다수 | 직장 지원 매뉴얼 |
| 공공기관 안전 매뉴얼 | 다수 | 직장 안전 지침 |
| 자체 시나리오 | 80개 | 직무지도 체크리스트 |

## 태스크 구성 (500개)
| 태스크 | 건수 |
|---|---|
| 근로지원 상황대응 | 120 |
| 쉬운 설명 변환 | 90 |
| 관리자 응대 가이드 | 80 |
| 직무지도 체크리스트 | 80 |
| 안전 위험상황 | 70 |
| 노동권·노동상식 | 40 |
| 고객서비스·직장매너 | 20 |

## 왜 OLMo인가
> OLMo가 가중치를 공개했기 때문에
> 발달장애 직장 도메인 데이터로 직접 파인튜닝이 가능했다.
> GPT-4 등 닫힌 모델은 API만 제공하므로 도메인 특화 불가.

## 기대 효과
- 직장 내 의사소통 표현 반복 훈련
- 상황별 적절한 언어 선택지 학습
- 관리자/동료 응대 시뮬레이션
- 언제 어디서나 접근 가능한 AI 피드백

## 확장 방향
- 한국어 특화 토크나이저 교체
- 데이터 규모 확장 (500 → 5000개)
- SKT NUGU / A.에이닷 인터페이스 연동
- 실시간 직장 상황 STT 입력 지원
